# 無料のツールで FIELDCRAFT を開発する

現在の JavaScript + Three.js + Vite の構成を継続します。新しい機能を作るために、Unreal Engine や有料素材を導入する必要はありません。

## 自分の PC に何が必要？

| やりたいこと | PC に必要なもの |
| --- | --- |
| 完成したゲームで遊ぶ | Chrome / Edge などの PC ブラウザ。`fieldcraft.html` を保存して開く |
| Codex に機能追加を依頼する | ブラウザ。開発用ライブラリはクラウド環境に導入済み |
| 自分でもコードを編集する | Node.js 24 LTS。編集には VS Code を推奨 |
| 変更履歴を GitHub に保存する | GitHub アカウントと Git または GitHub Desktop。必要になってから追加できる |

遊ぶだけなら、Node.js・Git・VS Code のインストールは不要です。Codex の利用料金は、自分が使っている契約に従います。

## 使用するツールと料金

| 名前 | 用途 | 料金・導入場所 |
| --- | --- | --- |
| JavaScript | ゲームのプログラムを書く言語 | 無料。ブラウザと Node.js が実行する |
| Node.js 24 LTS | 開発サーバー、テスト、配布用ファイルの生成 | 無料。クラウド導入済み。PC で編集するなら PC にも導入 |
| npm | ライブラリをまとめて導入する | 無料。Node.js に同梱 |
| Three.js | 3D の描画 | 無料。`npm ci` でプロジェクトに導入 |
| Vite | 開発サーバーと配布用ビルド | 無料。`npm ci` で導入 |
| Playwright | ブラウザの操作テスト | 無料。`npm ci` で導入。テスト用ブラウザの追加取得は任意 |
| Chrome / Edge | ゲームを開いて操作する | 無料。PC に既にあれば追加不要 |
| Visual Studio Code（VS Code） | コードの編集とターミナル操作 | 無料。自分で編集する場合に推奨 |
| Git / GitHub Desktop | コードの変更履歴を記録・同期する | 無料。GitHub Desktop は Windows / macOS 向け |
| GitHub Free | コードをオンラインに保存する | 無料プランで公開・非公開リポジトリを利用可能。有料機能や無料枠を超える利用は別料金 |

現在のゲームには、有料素材、課金 API、外部サーバー契約はありません。画像はゲーム内で生成しています。GitHub Actions などのクラウド自動実行や、有料の拡張機能も必須ではありません。

## PC で編集する準備

### 1. Node.js を入れる

1. [Node.js 公式ダウンロード](https://nodejs.org/en/download)を開きます。
2. バージョンは **24 LTS** を選びます。LTS は長期間サポートされる版です。
3. Windows は Windows 用 `.msi`、Mac は macOS 用 `.pkg` をダウンロードします。
4. ダウンロードしたファイルを開き、通常の設定のままインストールします。npm も一緒に入ります。
5. インストール後、起動中のターミナルや VS Code をいったん閉じて開き直します。

プロジェクトの `.nvmrc` は、クラウドで確認した Node.js の版を記録するファイルです。初心者の方は、まず Node.js 24 LTS のインストーラーを使えば進められます。

### 2. VS Code を入れる

1. [VS Code 公式サイト](https://code.visualstudio.com/)を開き、自分の OS 用をダウンロードします。
2. ダウンロードしたインストーラーを開きます。
3. VS Code を起動します。拡張機能は、最初は追加しなくても開発できます。

### 3. 現在のソースコードを保存する

1. [GitHub の tst-game](https://github.com/shien0zero-ai/tst-game) を開きます。
2. ブランチが `main` になっていることを確認し、「Code」→「Download ZIP」を選びます。
3. ダウンロードした ZIP を展開します。Windows は ZIP を右クリックして「すべて展開」、Mac は ZIP をダブルクリックします。
4. 展開後の `tst-game-main` フォルダー内に、`package.json` と `src` があることを確認してください。

このチャットの開発用 ZIP `fieldcraft-source.zip` も使えます。その場合は展開後のフォルダー名が `tst-game` になります。今後の最新版を取得するときは GitHub を使ってください。

ゲームを遊ぶための `fieldcraft.html` と、開発用のソース ZIP は用途が違います。コードを編集するときは ZIP に入っているソース一式を使います。

### 4. フォルダーを開いて、ライブラリを導入する

1. VS Code の「ファイル」→「フォルダーを開く」で、展開した `tst-game-main`（チャットの ZIP なら `tst-game`）を選びます。
2. 「ターミナル」→「新しいターミナル」を選びます。
3. 次を一行ずつ入力し、各行の後に Enter を押します。

```sh
node --version
npm --version
npm ci
```

Node.js の表示が `v24...`、npm が数字のバージョンなら準備できています。`npm ci` は必要なライブラリをまとめてダウンロードするため、最初はインターネット接続が必要です。

`package-lock.json` にライブラリの正確な版が保存されています。これと `npm ci` を使い、別の PC でも同じ依存関係を導入します。`node_modules` は自動生成されるため、ZIP に含めたり GitHub に送ったりする必要はありません。

Windows の PowerShell で「スクリプトの実行が無効」という npm のエラーが出た場合は、ターミナルのメニューから「コマンド プロンプト」を選び、同じフォルダーでもう一度実行できます。`node` が見つからない場合は、VS Code を再起動してから確認してください。

## ゲームを起動して編集する

同じターミナルで実行します。

```sh
npm run dev
```

自分の PC のターミナルに表示された `Local` のアドレスをブラウザで開きます。ゲームの「世界に入る」をクリックすると操作できます。ソースを保存すると、ブラウザ側にも変更が反映されます。

開発サーバーを動かしているターミナルは、そのまま開いておきます。終了するときはそのターミナルで **Ctrl + C** を押します。

このチャットの `/workspace/tst-game` はクラウド内のパスです。自分の PC でそのパスを入力する必要はありません。VS Code で自分が保存したフォルダーを開いてから、コマンドを実行してください。

## 変更を確認して、遊べるファイルを作る

VS Code で別のターミナルを開き、用途に合わせて実行します。

| コマンド | 行うこと |
| --- | --- |
| `npm test` | 地形・ブロック編集・衝突・ジャンプなどの自動テスト |
| `npm run build` | `dist` フォルダーに配布用のファイルを生成 |
| `npm run export` | `artifacts/fieldcraft.html` に、サーバー不要の 1 ファイル版を生成 |

`npm run export` でできた HTML は、自分の PC の Chrome / Edge で開いて遊べます。プログラムを修正したら、もう一度このコマンドを実行すると更新されます。

### ブラウザの自動操作テストも使いたい場合

初回だけ、テスト用の Chromium をダウンロードします。これは無料です。

```sh
npm run test:browser:install
```

一つ目のターミナルで `npm run dev` を実行したまま、二つ目のターミナルで次を実行します。

```sh
npm run test:browser
```

移動、マウス視点、ジャンプ、ブロックの設置・破壊、一時停止などを自動確認し、`artifacts` に画面画像を保存します。既にあるシステム Chromium を使う場合もあり、クラウド環境では導入済みのブラウザを再利用します。ブラウザの取得は一度済ませれば、通常は毎回やり直す必要はありません。

プレイ中は **Esc** で一時停止し、マウス感度を調整できます。10〜300% の範囲で変更でき、標準は 100% です。感度は同じブラウザに自動保存します（ワールドの編集内容を保存する機能とは別です）。ブラウザの保存が無効でも、その起動中の感度変更は使えます。

## GitHub Desktop で変更履歴を管理する

ローカルのソース一式を ZIP で保管する方法でも、開発は続けられます。変更履歴を残したり、複数の PC でコードを共有したくなったら、[GitHub Desktop](https://desktop.github.com/)を追加できます。公式インストーラーを開き、GitHub アカウントでサインインします。

このゲームの保存先は **`shien0zero-ai/tst-game`** です。次のいずれかで自分の PC に取得できます。

- ブラウザ：`https://github.com/shien0zero-ai/tst-game` を開き、「Code」→「Download ZIP」を選び、ダウンロードした ZIP を展開します。
- GitHub Desktop：「File」→「Clone repository」→「URL」で `https://github.com/shien0zero-ai/tst-game` を入力し、PC 内の保存先を選んで「Clone」を押します。

GitHub Desktop で clone したフォルダーを編集した場合は、次の手順で変更を保存できます。

1. GitHub Desktop の「Changes」で、変更したファイルを確認します。
2. 「Summary」に変更の説明を書き、「Commit to main」を押します。これは PC 内に変更履歴を保存する操作です。
3. 「Push origin」を押すと、GitHub にも送信されます。

ブラウザから「Download ZIP」で取得したフォルダーには Git の履歴がありません。GitHub Desktop で履歴を管理する場合は、上の「Clone repository」で取得したフォルダーを使ってください。`node_modules`、`dist`、`artifacts` は生成物なので、プロジェクトの `.gitignore` で送信対象から外しています。

GitHub の公開・非公開は「ソースコードを誰が見られるか」という設定です。Codex の「環境の公開」は開発環境の保存で、ゲームを誰でも開ける Web サイトにする操作とは別です。ゲームの Web 公開を希望する場合は、その時点で無料の方法と必要な操作を案内します。

## 今後の開発ルール

- ツールを追加する場合は、名前・用途・無料か有料かを説明します。必要な依存関係は、可能な範囲で自動セットアップします。
- 自分の PC での手動操作が必要な場合は、ダウンロード先、操作する画面、実行するコマンドを具体的に案内します。
- JavaScript + Three.js の現在の構成を優先します。別の制作環境への大きな移行は、理由とメリットを説明する前に進めません。
- 有料サービスや素材が必要になる場合は事前に知らせ、無料の代替案も示します。課金が発生する操作を自動で実施しません。
- セーブ機能、地形の拡張、操作改善などは、小さく実装し、テストと実際の操作を確認しながら追加します。
