# コメント付きコードの読み方

ゲームの処理を理解しながら変更できるよう、自作の JavaScript・CSS・HTML・SVG・テスト・配布用スクリプトに日本語コメントを付けています。処理を無効にする「コメントアウト」ではなく、実行するコードの横や上に説明を添える形です。

## どこから読む？

| 順番 | ファイル | 分かること |
| --- | --- | --- |
| 1 | `index.html` | 画面の部品と、それぞれの id の役割 |
| 2 | `src/main.js` | 起動、入力、毎フレームの更新、各機能のつながり |
| 3 | `src/world.js` | ブロックの保存方法、草原と木の生成、照準の判定 |
| 4 | `src/physics.js` | 移動、ジャンプ、床・壁との衝突、安全な場所への復帰 |
| 5 | `src/render.js` | Three.js での描画、ブロックの模様、見える面の組み立て |
| 6 | `src/settings.js` | マウス感度の制限とブラウザへの保存 |
| 7 | `src/style.css`、`src/settings.css` | 各画面の見た目、小さいウィンドウへの対応 |
| 8 | `tests/` 内のファイル | 何を操作し、どんな結果なら正しいと判断するか |
| 9 | `scripts/export-standalone.mjs` | ゲームを 1 個の HTML ファイルにまとめる仕組み |

`public/favicon.svg` はブラウザのタブに表示する図形です。最初からある `game` ファイルは改行のみで、実行するプログラムは入っていません。

## コメントの書き方

JavaScript は `//` から行末、または `/* ... */` を説明として扱います。

```js
// プレイヤーの左右の向きを、マウスを動かした量だけ変える。
yaw -= event.movementX * lookSpeed;
```

CSS では `/* ... */`、HTML・SVG では `<!-- ... -->` を使います。既存の処理を `//` などで囲って無効にするとゲームの動作が変わるため、説明を追加するときは実行するコードを残します。

## package.json の説明

JSON は仕様上コメントを書けません。ファイル内に `//` や `/* ... */` を書くと npm が読み込めなくなるため、説明はこちらにまとめています。

| 項目 | 役割 |
| --- | --- |
| `name` | npm 上のプロジェクト名。このプロジェクトでは `fieldcraft` |
| `version` | プロジェクトのバージョン番号 |
| `private: true` | 誤って npm のパッケージとして公開しないための設定。GitHub の公開・非公開とは別 |
| `type: "module"` | JavaScript で `import` / `export` を使うための設定 |
| `engines.node` | 必要な Node.js の最低バージョン。推奨バージョンは `.nvmrc` に記録 |
| `scripts` | `npm run 名前` で実行するコマンドの一覧 |
| `dependencies` | ゲーム本体に必要なライブラリ。現在は 3D 描画用の Three.js |
| `devDependencies` | 開発・ビルド・テストに使うライブラリ。現在は Vite と Playwright |

### scripts に登録しているコマンド

| 名前 | コマンドが行うこと |
| --- | --- |
| `dev` | Vite の開発サーバーを起動。`--host 0.0.0.0` はクラウドなどでも接続を受け付けられるようにする指定で、公開 URL の発行ではない |
| `build` | Vite でコードを配布用に変換し、`dist/` に出力 |
| `export` | `build` が成功したあと、配布用コードを 1 ファイル版 HTML にまとめる |
| `preview` | `dist/` のビルド結果を確認するためのローカルサーバーを起動 |
| `test` | Node.js 標準のテスト機能で `tests/*.test.js` を実行。`--test-isolation=none` は各ファイルを別プロセスに分けずに実行する指定 |
| `test:browser:install` | Playwright が使うテスト用 Chromium を導入 |
| `test:browser` | 実際のブラウザを操作するテストを実行。対象のサーバーは先に起動しておく |

## package-lock.json の説明

これも JSON なので、直接コメントを書きません。npm が自動管理するため、通常は手作業で編集せず、`npm install` や `npm ci` を使います。

| 項目 | 役割 |
| --- | --- |
| `name`、`version` | 対象プロジェクトの名前とバージョン |
| `lockfileVersion` | npm が使うロックファイル形式のバージョン |
| `requires` | 依存関係情報を扱うための npm の管理項目 |
| `packages` | プロジェクト本体と、間接的な依存も含めた各パッケージの一覧 |
| `packages[""]` | このプロジェクト自身の依存関係と Node.js 条件 |
| 各パッケージの `version` | 実際に導入する正確なバージョン |
| `resolved` | 配布ファイルの取得元 |
| `integrity` | ダウンロードした内容が正しいか検証するための値 |
| `dependencies`、`engines`、`os`、`cpu` | 必要な別パッケージや、動作する実行環境の条件 |
| `bin` | コマンドとして起動できる実行ファイルの情報 |
| `dev`、`optional`、`hasInstallScript`、`license` | 開発用・任意の依存か、導入時の処理があるか、ライセンスは何か、といった管理情報 |

これらの情報を固定することで、別の PC でも `npm ci` で同じ依存関係を導入できます。

## その他の設定と生成物

- `.nvmrc`: 推奨する Node.js の正確なバージョンを 1 行で記録します。バージョン管理ツールが読み取るため、説明はこのガイドに置いています。
- `.gitignore`: Git に保存しないファイルを指定します。各行の目的はファイル内の `#` コメントで説明しています。
- `AGENTS.md`: 今後の開発で守る方針です。新しい処理にも日本語コメントを添えることを記録しています。
- `node_modules/`: 導入した外部ライブラリ本体です。手を加えず、必要な説明は自作コード側に書きます。
- `dist/`、`artifacts/`: ビルドや配布用の生成物です。説明や処理を変更するときは元のコードを直し、`npm run export` などで作り直します。

配布用 JavaScript は読み込みを軽くするため、ビルド時にコメントや空白が省かれます。学習や編集には、GitHub またはソース ZIP に入っている `src/` などを使ってください。
